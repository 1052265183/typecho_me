- AIX-WORK 配置: C:\Users\huxu\.dsh\aix-work-config.json (mcpPaths)

## 现象

+ error: "Error: HTTP POST failed: Error: HTTP 0: " + healthStatus: red

## 复现步骤

1. 在 C:\Users\huxu\AI\.mcp.json 添加 http 类型 MCP server，url 用 HTTPS、tls_required=true
   （示例：baota-mcp，url 是 https://172.29.51.111:8765/...，服务端是自签证书）
2. 启动 DSH（DSH 加载 .mcp.json）
3. 在 DSH 里跑：aix_work_diag section=mcp
4. 观察 baota-mcp 状态：connected: false、tools: 0、error 包含 "HTTP 0: " 或 SSL 错误

## 当前行为

AIX-WORK 插件的 httpPostWithHeaders 函数 (lib/index.js line 422-466) 用 curl
命令行作为 HTTP 客户端调用 MCP HTTP API：

  async function httpPostWithHeaders(url, body, headers) {
    const argv = ["curl", "-s", "-S", "-D", "-", "-X", "POST",
                  "-H", "Content-Type: application/json",
                  "-H", "Accept: application/json, text/event-stream",
                  "-d", JSON.stringify(body), "--max-time", "30"];
    if (headers) for (const k in headers) { argv.push("-H"); argv.push(k + ": " + headers[k]); }
    argv.push(url);
    const spec = { argv, cwd: ..., stdio: ..., graceMs: 10000 };
    const handle = subprocess.spawn(spec);
    ...

具体问题（4 个子问题）：

  1. 没传 --cacert 或 CURL_CA_BUNDLE 环境变量 → 无法指定自定义 CA 证书
  2. 没传 -k / --insecure → 无法跳过 TLS 验证（开发/自签证书场景）
  3. 没传 --resolve → 无法处理 hostname mismatch（访问 IP 与证书 SAN 不符）
  4. 错误信息不区分 SSL / 网络 / 协议错误（line 507 统一 error: String(e)）→ 排查困难
  5. runHealthCheck (line 716-719) 用同样 curl argv 但也没传 TLS 参数 → health check
     永远返回 cn=0 ("No response")，即使 MCP 服务正常

子问题 #5（架构一致性）：
  - stdio transport (line 380-418) 透传 config.env 给子进程（line 383）：
      env: Object.assign({}, process.env, config.env || {})
  - http transport (line 479-490) 完全忽略 config.env：
      const hdrs = config.headers || {};
      ...
      const initResp = await httpPostWithHeaders(url, ..., hdrs);  // ← 只传 headers
  - 两个 transport 行为不一致：stdio 支持 env，http 不支持

## 期望行为

至少支持以下任一方式配置 HTTP MCP 的 TLS：

  A. 读 config.env 字段（与 stdio 一致），透传给 curl 子进程，
     至少支持：CURL_CA_BUNDLE（指定 CA）/ CURL_INSECURE=1（跳过验证）

  B. 给 MCP config 加结构化 tls 字段：
      {
        "mcpServers": {
          "baota-mcp": {
            "type": "http",
            "url": "...",
            "headers": {...},
            "tls": {
              "caFile": "C:\\Users\\huxu\\.claude\\baota_root_ca.crt",
              "insecure": true   // 跳过 hostname 验证（仅开发）
            }
          }
        }
      }

  C. Config schema 校验时把 env 字段纳入 http 类型（stdio 已经支持）

## 根因分析

AIX-WORK 用 curl 而非 Node https/fetch 作 HTTP 客户端（设计选择：Windows 上 curl 处理
TLS 比较稳），但没透传任何 TLS 配置给 curl 子进程。这与 stdio transport (line 383) 透传
env 的行为不一致，破坏了"stdio / http 都支持 env"的隐式契约。

另外 connectMcpServer (line 474-510) 调用 httpPostWithHeaders 时签名只接
(url, body, headers) 三个参数，没接受 config 对象，无法读取 env / tls。

错误归因不细（line 507 统一 error: String(e)）也加剧排查难度——用户看到 "HTTP 0:"
不知道是 SSL、TLS hostname、TCP 拒绝还是协议错误。

### 改法 1（最小侵入：支持 env 透传）

  修改 httpPostWithHeaders 签名，接受 extraEnv 参数，把 TLS 相关 env 转成 curl flag：

    async function httpPostWithHeaders(url, body, headers, extraEnv) {
      const argv = ["curl", "-s", "-S", "-D", "-", "-X", "POST",
                    "-H", "Content-Type: application/json",
                    "-H", "Accept: application/json, text/event-stream",
                    "-d", JSON.stringify(body), "--max-time", "30"];
      if (headers) for (const k in headers) { argv.push("-H"); argv.push(k + ": " + headers[k]); }
      // 把 env 里的 TLS 配置转成 curl 参数
      if (extraEnv) {
        if (extraEnv.CURL_CA_BUNDLE) {
          argv.push("--cacert"); argv.push(extraEnv.CURL_CA_BUNDLE);
        }
        if (extraEnv.CURL_INSECURE === "1" || extraEnv.CURL_INSECURE === "true") {
          argv.push("-k");
        }
      }
      argv.push(url);
      // 透传 env 给 curl（让 CURL_CA_BUNDLE 等生效）
      const spec = {
        argv, cwd: state.config.basePath || process.cwd(),
        stdio: { stdin: "ignore", stdout: { maxBytes: 10485760 }, stderr: { maxBytes: 1048576 } },
        env: extraEnv || {}, graceMs: 10000
      };
      ...
    }

  修改 connectMcpServer line 479-490，传入 config.env：

    if (config.type === "http") {
      const url = config.url;
      const hdrs = config.headers || {};
      const extraEnv = config.env || {};
      const initResp = await httpPostWithHeaders(url, {...}, hdrs, extraEnv);
      ...
    }

### 改法 2（更结构化：加 tls 字段）

  Config schema 增加 tls 字段（建议放在 httpPostWithHeaders 内部解析），
  支持 caFile / insecure / serverName 等选项。

### 改法 3（统一 env 透传，与 stdio 一致）

  即便不改 curl 参数，也把 config.env 透传给 curl 子进程（通过 spec.env），
  这样 CURL_CA_BUNDLE 等标准 curl 环境变量也能生效。这是最小修改。
