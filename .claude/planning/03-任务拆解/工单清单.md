## P0 核心维护（代码缺口）

### G5：代码块复制按钮兜底修复

- **优先级**：P0 ｜ **状态**：已完成 ｜ **预估**：小
- **背景**：`typecho-GAPS.md` G5。`footer.php` 的 `injectCopyButtons()` 只用 `navigator.clipboard`，违背已采纳的 `ADR-001` 决策 4（要求 execCommand 兜底）与备选 C（否决"仅用 clipboard"）；正式环境为 http，`navigator.clipboard` 为 `undefined`，点击必抛 `TypeError`。同时 `copy-page.js` 的 `fallbackCopy()` 只挂 `.catch()`，而 ADR-001 背景 3 记录 http 下 Promise 会静默挂起，`.catch()` 永不触发。
- **方案**：`ADR-002`（决策 1~5）。
- **验收标准**：
  1. 代码块逻辑外置为 `static/js/copy-code.js`，`footer.php` 内联脚本不再包含注入逻辑。
  2. 剪贴板写入为三段式：clipboard API → 超时（默认 800ms）→ `execCommand("copy")`，两条复制路径共用同一份兜底实现。
  3. 代码块与整页按钮均走 `document` 事件委托，PJAX 换页后新按钮可触发。
  4. `pjax:complete` 重跑注入、已注入的 `<pre>` 跳过，防重复。
  5. 删掉本地多出的 `remove("icon-duhao")` 拼写笔误行。
  6. `php -l` 通过 + 浏览器实测两个复制按钮在 http 下均有成功反馈。
- **验收记录**（2026-09-28，本地 `http://127.0.0.1:8000` 实测）：
  - `php -l` 通过（footer/index/post）；`node --check` 三个 JS 文件通过；页面无 JS 报错、无 console 错误。
  - 三个脚本均加载（`__WD_CLIPBOARD_JS_LOADED` / `__COPY_CODE_JS_LOADED` / `__COPY_PAGE_JS_LOADED` 均为 true）；4 个 `<pre>` 注入 4 个按钮；整页按钮 1 个；首屏 `loader=hidden`、`body=block` 未卡死。
  - **降级路径**：移除 `navigator.clipboard` 后派发点击，图标 class 变为 `icon-duihao text-success`——证明 API 缺失时走 `execCommand` 兜底而非抛 `TypeError`（修复前必然抛）。
  - **整页复制**：按钮加 `is-copied`、正文加 `copy-flash`，符合 ADR-001 决策 6。
  - **PJAX 场景**：替换 `#main` 后按钮数 4→0，触发 `pjax:complete` 后回到 1——复现并修复了 ADR-001 背景 1 的核心故障。
  - 遗留观察：非安全上下文（真 http 部署）的 `execCommand` 返回值需在正式环境再确认一次，本次实测环境为 `127.0.0.1`（安全上下文），降级分支是靠摘除 API 模拟触发的。
- **依赖**：无。发布链路见 CLAUDE.md §0.6。

### G6：`download-proxy.php` 安全加固

- **优先级**：P0 ｜ **状态**：待启动 ｜ **预估**：中
- **背景**：`typecho-GAPS.md` G6（SSRF / 零鉴权可写盘 / SVG 漏网 / 关闭 TLS 校验 / PHP 8 命名参数 / 报错泄露，共六项）。插件已按决定全量入库，缺陷挂本工单跟踪；修复前该端点不应暴露在公网。
- **验收标准**：
  1. 请求 URL 加白名单，或至少拒绝内网与环回段（`127.0.0.0/8`、`10/8`、`172.16/12`、`192.168/16`、`169.254/16`、`::1`、`fc00::/7`）及非 `http(s)` 协议。
  2. 端点加鉴权（Typecho 登录态或签名 token），未授权请求直接拒绝且不触发出网。
  3. 扩展名校验改为图片白名单，或至少把 `svg` 补进封禁列表。
  4. 恢复 TLS 校验：删除 `CURLOPT_SSL_VERIFYPEER` / `CURLOPT_SSL_VERIFYHOST` 置 false 与 `ssl.verify_peer` / `verify_peer_name` 置 false。
  5. 去掉 PHP 8.0 命名参数（`ini_set('log_errors', value: 0)` → `ini_set('log_errors', 0)`），保证 PHP 7.4 可解析。
  6. 失败分支的 `debug` 字段不再回显服务器绝对路径与原始 URL。
  7. `php -l` 在 PHP 7.4 与 8.2 下均通过（口径见 CLAUDE.md §5）；对内网地址与非白名单域名的请求返回拒绝且不产生出网流量。
- **依赖**：无。
- **备注**：修复涉及行为变更（鉴权会影响后台正常上传），动手前先确认调用方——`Plugin.php` 与 `custom.js` 走的是 `upload.php`，`download-proxy.php` 目前由前端自定义逻辑直接 POST。
